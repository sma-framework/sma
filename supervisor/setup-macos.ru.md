# SMA V5 — запуск парка работников 24/7 на Mac mini (launchd)

*English version: [`setup-macos.md`](setup-macos.md).*

Это первичная настройка выделенного хоста для парка работников. Ядро демона
host-agnostic; здесь только тонкая привязка к macOS через launchd. Это
macOS-двойник [`setup-windows.ru.md`](setup-windows.ru.md): тот же порядок, тот же
смоук-принцип, другой супервизор.

Порядок ниже рассчитан на ЛЮБОЙ хост с macOS, а не на конкретную машину или дом.
Первый внешний прогон этой инструкции, скорее всего, сделает бета-тестер — на
СВОЁМ Mac mini со СВОИМИ учётными записями. Поэтому:

- Шаги 1-8 (базовая настройка + смоук + локальный демон + ростер) должны пройти на
  любом Mac mini: их выполняют и владелец, и бета-тестер одинаково.
- Шаг 9 «Возврат работы владельцу» — это ОТДЕЛЬНЫЙ путь park-host: он нужен, только
  когда mini держит у себя работу владельца (его клон, его задачи). Бета-тестеру,
  который просто гоняет смоук и локального демона у себя, шаг 9 не нужен.

Шаги, которые выполняет человек руками, написаны простым языком, формально на «Вы».
Инженерные детали идут ниже отдельными блоками.

> **Про безопасность.** Демон никогда не обращается к origin: у него нет пути к
> глаголу публикации. Публикацию в main всегда делает владелец со своей машины
> (`/sma-ship`). Одобренная на mini работа возвращается обратным путём — владелец
> добавляет mini как git-remote и подтягивает её сам (шаг 9). Клон на mini
> физически не может опубликовать: его push-адрес отключён (шаг 4).

---

## 1. Пользователь с автологином

Заведите на Mac mini ОТДЕЛЬНОГО пользователя для работника (например `worker`) и
включите для него автоматический вход в систему: **Системные настройки →
Пользователи и группы → Автоматический вход → выберите этого пользователя**. Так
mini после перезагрузки сам входит в сессию работника, launchd поднимает демона
(RunAtLoad), и все учётные записи работают под этим пользователем.

> Почему автологин, а не запуск при загрузке без пользователя. Работники запускают
> `claude` и `codex`, а их авторизация ПРИВЯЗАНА К ПОЛЬЗОВАТЕЛЮ (токены
> `claude setup-token`, папка `~/.claude`, отдельный `CLAUDE_CONFIG_DIR` на каждый
> аккаунт). Фоновая служба без сессии (LaunchDaemon) этой авторизации и Keychain
> может не получить. Поэтому 24/7-форма — это LaunchAgent под
> автологин-пользователем.

## 2. Homebrew и базовые пакеты

Установите Homebrew (если ещё нет), затем node, git и Postgres:

```bash
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
brew install node git postgresql@16
brew services start postgresql@16     # локальная база очереди на хосте
which node                            # запомните путь: Apple Silicon -> /opt/homebrew/bin/node
```

> Путь к node важен для plist (шаг 7). На Apple Silicon это `/opt/homebrew/bin/node`,
> на Intel-mini — `/usr/local/bin/node`. Возьмите то, что показал `which node`.

## 3. Глобальные CLI работников (проверьте точные имена пакетов)

```bash
npm install -g @anthropic-ai/claude-code
npm install -g @openai/codex
claude --version && codex --version   # обе команды должны напечатать версию
```

> Точные имена пакетов здесь не перепроверялись (обе CLI уже работают на
> референс-машине Windows). Если `claude`/`codex` не находятся после установки —
> сверьте актуальное имя пакета у вендора и поправьте команду. Смоук (шаг 5)
> проверит, что обе команды отвечают.

## 4. Клоны репозиториев (origin — только на чтение)

Работник получает СВОИ клоны — он никогда не делит рабочую копию владельца.
Клонируйте продукт SMA и, если этот mini будет держать задачи владельца, ваш
рабочий репозиторий. Сразу после клона ОТКЛЮЧИТЕ у origin адрес публикации, чтобы
клон физически не мог опубликовать:

```bash
cd ~
git clone <SMA_REPO_URL> sma
git clone <YOUR_REPO_URL> project          # только если mini держит задачи владельца

# сделать origin доступным ТОЛЬКО на чтение (fetch-only) в каждом клоне:
cd ~/sma       && git remote set-url --push origin DISABLED
cd ~/project   && git remote set-url --push origin DISABLED
git remote -v                              # у origin должен стоять (fetch), а push -> DISABLED
```

> `DISABLED` — это заведомо нерабочий адрес: любая попытка публикации из клона
> немедленно падает. Это третий слой закона «публикует владелец» (первые два —
> отсутствие пути к глаголу публикации в исходниках демона и локальный-только
> глагол слияния).

## 5. Смоук кроссплатформенности — ЭТО ПЕРВЫЙ ШАГ ПОСЛЕ КЛОНОВ

Прежде чем настраивать демона, докажите, что вербы SMA и хост-предпосылки работают
на macOS. Вся обвязка до сих пор гонялась ТОЛЬКО на Windows — этот смоук принимает
её на macOS:

```bash
cd ~/sma
node supervisor/smoke-macos.mjs
```

Смоук — это последовательный чек-лист: каждый шаг печатает `PASS` или `FAIL` и идёт
дальше, а в конце процесс завершается числом падений (выход 0 = всё зелено). Он
проверяет:

1. node >= 22.5 + git в PATH.
2. полный прогон `pnpm test` в `~/sma` (единоразовая приёмка всей сьюты на этой
   машине).
3. живой круг `worktree provision` → проверка базы → `worktree remove`.
4. круг `statusline install` → render → uninstall.
5. POSIX-ветку установки хуков (на настоящем macOS не запускалась ни разу).
6. `claude --version` + `codex --version` (проверка имён пакетов из шага 3).
7. поднятый postgresql@16 + `psql -c 'select 1'`.
8. изоляцию `CLAUDE_CONFIG_DIR` на два аккаунта.

Сообщите владельцу итог смоука (сколько PASS из скольких). Красные шаги — это
список того, что надо доустановить или поправить перед следующими шагами.

## 6. Токены аккаунтов и конфиг демона

На каждый Max/Pro-аккаунт из пула сделайте headless-токен и положите его в
переменную окружения того пользователя, под которым работает демон:

```bash
claude setup-token                    # повторить на каждый аккаунт, под его CLAUDE_CONFIG_DIR
```

Токены храните в env-файле с правами 0600 (только владелец читает), НИКОГДА не в
git и не в самом конфиге демона:

```bash
umask 077
printf 'export SMA_MAX_1_TOKEN=...\nexport SMA_MAX_2_TOKEN=...\nexport SMA_MAX_3_TOKEN=...\nexport SMA_PRO_1_TOKEN=...\n' > ~/.sma-daemon/tokens.env
chmod 600 ~/.sma-daemon/tokens.env
```

Конфиг демона создаётся при первой загрузке со свежим 64-символьным токеном фронта.
Создайте его заранее и заполните:

```bash
cd ~/sma
node --input-type=module -e "import('./daemon/src/config.mjs').then(m=>m.loadConfig())"
```

В `~/.sma-daemon/config.json` задайте:

- `queueUrl` = `postgres://localhost:5432/sma_daemon` — локальная база очереди на
  хосте. НИКОГДА не рабочая база вашего проекта и НИКОГДА не продакшн-база.
- `bind` — `127.0.0.1` для проверки локально; `0.0.0.0` только осознанно, чтобы
  ростер открывался с других устройств по LAN.
- `expireMs` — сколько работник может молчать, прежде чем его задачу заберут
  обратно, в миллисекундах (по умолчанию `120000`, две минуты). Одна настройка —
  одни часы: это же число служит и арендой самой очереди, и подметанием, которое
  возвращает задачу молчащего работника, поэтому увеличение двигает оба. Всё, что
  не является положительным числом, игнорируется — остаётся значение по умолчанию.
- `workers` — аккаунты пула: у каждого свой `account.configDir` и имя
  env-переменной с токеном в `account.oauthTokenEnv` (значение токена живёт только
  в окружении, не на диске).
- `token` (фронт-токен) остаётся как сгенерирован — им вы откроете ростер.

> **Про режим 0600.** Конфиг демона несёт фронт-токен и пишется в режиме 0600.
> Env-файл с OAuth-токенами — тоже 0600. Ни токен, ни имена env-переменных никогда
> не печатаются: всё логируемое проходит через `secretsView`, который сворачивает
> секреты в `[set]`/`[unset]`.

## 7. Установка LaunchAgent

Скопируйте шаблон plist в `~/Library/LaunchAgents`, замените в КОПИИ два
плейсхолдера и загрузите агент:

```bash
cp ~/sma/supervisor/com.sma.daemon.plist ~/Library/LaunchAgents/com.sma.daemon.plist
# в копии заменить:
#   <SMA_HOME>    -> абсолютный путь клона (например /Users/worker/sma)
#   <WORKER_HOME> -> домашняя папка пользователя (например /Users/worker)
# и при необходимости путь к node (Intel: /usr/local/bin/node)

launchctl load -w ~/Library/LaunchAgents/com.sma.daemon.plist
launchctl list | grep com.sma.daemon           # демон должен быть в списке
tail -f ~/Library/Logs/sma-daemon.log          # логи демона
```

Агент стоит с `KeepAlive` — launchd перезапустит демона при любом падении. Снять
агент: `launchctl unload -w ~/Library/LaunchAgents/com.sma.daemon.plist`.

## 8. Проверка ростера со второго устройства

Если `bind` = `0.0.0.0`, откройте ростер с телефона/ноутбука в той же сети:
`http://<IP_МИНИ>:7777/?token=<ФРОНТ_ТОКЕН_ИЗ_КОНФИГА>`. Ростер должен показать
полосу состояния парка, очередь и карточки работников. Первое открытие с `?token=`
ставит HttpOnly-cookie — дальше токен в адресе не нужен.

Адрес здесь склеивается руками только потому, что браузер стоит на ДРУГОМ
устройстве. На машине самого демона его не склеивают: `node
scripts/sma/cli.mjs open` соберёт ту же одноразовую ссылку из конфига и откроет
её (`--print` вместо этого выпишет её строкой — для машины без браузера).

> Отложенное усиление (для первого прогона не требуется): по LAN сейчас обычный
> HTTP — это допустимо, потому что ростер несёт только метаданные задач, никогда не
> код-диффы без токена, никогда не токены подписок. Позже — mkcert/TLS или
> `tailscale serve`.

## 9. Возврат работы владельцу (путь park-host)

> ⚠ Этот шаг нужен ТОЛЬКО когда mini держит задачи владельца (его клон рабочего
> репозитория). Бета-тестеру, который гоняет смоук и локального демона у себя, шаг
> 9 пропустить.

Схема возврата: одобренная на mini работа лежит в локальном main его клона;
**владелец добавляет mini как git-remote на СВОЕЙ машине и подтягивает её сам** — у
демона и работника пути к origin нет вовсе.

```bash
# выполняет ВЛАДЕЛЕЦ на СВОЕЙ машине:
git remote add mini worker@<IP_МИНИ>:/Users/worker/project
git fetch mini
git log mini/main --oneline           # одобренные коммиты работника
# дальше владелец сам решает, что влить и опубликовать через свой /sma-ship
```

Альтернатива «демон сам публикует ветки `wt/*`» ОТКЛОНЕНА по умолчанию: она требует
явного исключения из закона «публикует владелец». Если владелец выберет другую
схему — поправьте этот шаг под неё.
